# ADR 0005: Separate execution, provenance, freshness, and binding authority

- Status: Accepted for CCA-240 v1 implementation
- Date: 2026-07-30
- Issue: CCA-240 / #9
- Exact authorized base: `36f09c2452e4a39455a717a3c1689b965e6de9ee`

## Context

Execution outcome, artifact provenance, policy-relative freshness, and exact-byte
composition change under different authorities and lifecycles. Combining them
would encourage unavailable execution to become pass, real evidence to become
fresh/sufficient, or a collection of evidence to become approval.

Public bindings of private evidence also create equality, dictionary, timing,
and disclosure-oracle risks. Freshness cannot be reproducible if an assessor
implicitly reads current time, mutable revisions, or live revocation services.

## Decision

Define four closed Draft 2020-12 contracts:

- `cryptocomm-execution-result/v1` preserves seven literal terminal states and
  status-specific occurrence/field/artifact-role semantics;
- `cryptocomm-evidence-provenance/v1` records explicit subject forms, exact input
  bytes, producer/tool/environment/scope identity, orthogonal origin/use axes,
  and public-content or private-opaque artifact references;
- `cryptocomm-freshness-assessment/v1` applies the fixed not-assessed,
  mismatched, stale, unknown, fresh decision order to caller-supplied facts;
- `cryptocomm-evidence-binding-set/v1` is the minimal root binding exact bytes of
  one record from each preceding authority.

A non-completed execution cannot bind a substantive result. Private opaque
references expose no plaintext digest, size, media type, storage/customer/path,
or private-storage metadata. Freshness assessment is pure and never reads a
clock/network/mutable revision implicitly. Diagnostics and generated bytes are
bounded and deterministic.

The evidence origin/use split allows only synthetic+test-only, real+test-only,
and real+policy-evaluable. It rejects synthetic+policy-evaluable.

## Consequences

Four records and explicit joins increase fixture and validator surface, but make
promotion and mix-and-match errors testable. Exact-byte bindings distinguish
semantically equal but differently encoded external artifacts. An always-present
freshness record represents no assessment with `not-assessed` rather than absence.

No status, classification, or freshness state decides evidence sufficiency,
claim satisfaction, human approval, certification, risk acceptance, or release.
A binding set is not evidence storage.

## Deferred and rejected alternatives

CCA-240 v1 does not define a private-sidecar contract, private storage, HMAC,
encryption/key lifecycle, access credentials, policy-decision contract,
revocation/trusted-time service, aggregate satisfaction/release contract, CLI,
or live probing. Caller-supplied lifecycle facts retain bounded authority IDs;
authority governance/distribution remains deferred.

Local read-only ae-framework and GenAI Repo Auditor field analysis remains design
input only. CCA-240 adds no adapter, upstream mapping authority, compatibility
contract, or compatibility claim. Later bridge Issues own that work.
